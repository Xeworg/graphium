# F0 — Spike técnico de Graphium

Feature ODD para el spike técnico F0 del PRD v1.7 (`docs/PRD.md` §12). F0 no construye producto: cierra decisiones técnicas con un camino end-to-end real (JSON → IR → layout → SVG propio → ventana-plano con grilla) y midiendo la matriz de capacidades de `dagre`.

Criterio de salida (PRD §12, verbatim): «Desde Pi: pido un diagrama → la ventana abre con el SVG de nuestro código sobre el plano; dagre: go/no-go documentado; **matriz RNF1-bis medida**.»

## Specs

- **S1** (PRD §12, F0): «Workspace + Tauri 2 + rmcp + mini motor end-to-end (layout trivial → SVG nuestro → ventana-plano con grilla) + **matriz de capacidades de `dagre` por test** + single-instance socket básico + **runtime tokio y render round-trip** (§8.6.1) + **frozen de fuente y tokens** (§8.5).»
- **S2** (PRD §12, criterio de salida F0): «Desde Pi: pido un diagrama → la ventana abre con el SVG de nuestro código sobre el plano; dagre: go/no-go documentado; **matriz RNF1-bis medida**.»
- **S3** (PRD §8.1-8.3, trait): «`pub trait DiagramKind: Send + Sync { const KIND: &'static str; const LAYOUT_HINT: LayoutHint; const LIMITS: KindLimits; type Input: JsonSchema + for<'de> Deserialize<'de>; fn validate(&self, input: &Self::Input) -> Result<(), Vec<ValidationError>>; fn to_ir(&self, input: &Self::Input) -> Ir; fn schema() -> schemars::schema::RootSchema; }`»
- **S4** (PRD §8.1-8.3, IR): «`enum Ir { Graph(IrGraph), Timeline(IrTimeline) }`», «`struct IrGraph { direction: Direction, layout_hint: LayoutHint, nodes: Vec<IrNode>, edges: Vec<IrEdge>, groups: Vec<IrGroup> }`», «`struct IrNode { id, label, shape, emphasis, style, meta, size: Size }`», «`struct IrEdge { from, to, label, emphasis, style, arrow }`», «`enum LayoutHint { Layered, Tree, Sankey, Git }`»
- **S5** (PRD §9.1, puerta única): «`gx_core::engine::render_json(src: &str, opts: &RenderOpts) -> Result<RenderOutcome, Vec<ValidationError>>` con `RenderOutcome { svg, layout, bbox, metrics }`; `gx-mcp` y los tests usan **exactamente** esta función: ningún test de RNF6 necesita Tauri, webkit ni webview.»
- **S6** (PRD §9.1, matriz de dependencias): «`gx-core` | — | `cargo tree -p gx-core` no lista `gx-kinds`»; «`gx-kinds` | `gx-core` | `cargo tree -p gx-kinds` no lista `gx-layout` ni `gx-render-svg`»; «`gx-layout` | `gx-core` **y nada más**»; «`gx-render-svg` | `gx-core`»; «`gx-mcp` | `gx-core` + `gx-kinds` **solo vía `registry::for_kind(&str)`**»; «`gx-app` | todo | `cargo tree -p gx-app` es el único árbol que puede listar `tauri` y `webkit2gtk` (RNF2)»
- **S7** (PRD §8.5.1, forma canónica): «Un único formateador `fmt_num(f64) -> String` (2 decimales, half-even, sin `-0`) usado en **todo** atributo numérico.» · «Los ids del SVG se derivan del id de la IR (`g-<id>`, `m-<from>-<to>`), **nunca** de contadores.» · «`<defs>` y los markers se emiten en **orden de id**; sin espacios finales, sin declaración XML, atributos en orden fijo.»
- **S8** (PRD §8.5, tokens congelados): «**Inter 400/600** (OFL, embebida, subset Latin-1 + Latin Ext-A, ~1.2 MB) · texto **14 px** · padding de nodo **12 px** · radio de esquina **6 px** · grosor de borde **1 px** · interlineado **1.25**»
- **S9** (PRD §8.5.2, paleta): «`pub struct Palette { theme: Theme, bg: Color, grid: Color, node_fill: Color, node_stroke: Color, node_text: Color, edge_stroke: Color, edge_text: Color, accent: Color }`» y «`pub enum Theme { Dark, Light }`»; el SVG lleva «clases CSS por token (`class="node-fill"`, `class="edge-stroke"`, …) y un bloque `<style>` con la **paleta resuelta**»
- **S10** (PRD §8.4, plan operativo dagre): «pin de versión exacta en `Cargo.toml`; F0 incluye una **matriz de capacidades** verificada por test (clusters, TB/BT/LR/RL, labels en edges, self-loops, nodos desconectados); trigger de vendoring: bloqueo F1 sin fix upstream en 2 semanas → vendor al workspace con atribución NOTICE.»
- **S11** (PRD §8.4.1, métricas): «`pub trait TextMetrics: Send + Sync { fn measure(&self, text: &str, style: &TextStyle) -> Size; }`» · «`gx-render-svg` implementa `TextMetrics` y es la **única** fuente de métricas.» · «`gx-layout` **recibe** el medidor como parámetro (`DagreEngine::new(metrics)`); no depende de `gx-render-svg` y **no mide texto**.»
- **S12** (PRD §9.1, escapado): «Todo texto que viene del JSON se emite **escapado** (`&` → `&amp;`, `<` → `&lt;`, `>` → `&gt;`, `"` → `&quot;`, `'` → `&#39;`) dentro de `<text>`; el SVG se inserta con `innerHTML` bajo CSP de Tauri `default-src 'self'` sin `unsafe-inline` para scripts.» · «Test: un `label` con `</text><script>…` produce SVG válido (parsea sin error) y ningún nodo `<script>` en el DOM.»
- **S13** (PRD §6.1, ejemplo mínimo `graph`): «`{ "version": 1, "kind": "graph", "title": "parse_config() — flujo", "direction": "TB", "nodes": [ { "id": "read", "label": "read file" }, { "id": "ok", "label": "Config" } ], "edges": [ { "from": "read", "to": "ok", "label": "utf-8" } ] }`»
- **S14** (PRD §8.6.1, runtime y round-trip): «Un `tokio` multi-hilo (`rt-multi-thread`) es el **único** runtime; `tauri::async_runtime` lo reutiliza. El transporte stdio de `rmcp` corre en un **thread dedicado** con runtime `current-thread` propio.» · round-trip: «1. Validar + IR + layout + SVG en `spawn_blocking`. 2. Si el webview no existe, crearlo y esperar `graphium://ready`. 3. Emitir `graphium://render { req_id, diagram_id, svg, place }`. 4. El frontend responde `render_ack { req_id, ok }` **después de dos `requestAnimationFrame`**. 5. Timeout de **2000 ms** → `ok: true, rendered: false, reason: "ui_timeout"`.» · razones: «`headless` · `no_window` · `ui_timeout` · `ui_error`»
- **S15** (PRD §8.6.1, modos de arranque): «`graphium --stdio` → modo MCP» · «`graphium` (sin argumentos, doble clic) → modo **solo-ui**» · «`graphium mcp-config [--client ...]` imprime `{"command": "<ruta absoluta del binario>", "args": ["--stdio"]}`»
- **S16** (PRD §8.6 + RNF9, single instance): «socket local (`$XDG_RUNTIME_DIR/graphium.sock`)» · «si el socket existe y el `connect` falla, el proceso **roba** el socket (unlink + bind) y loguea `owner_takeover`» · «Máximo **8 sesiones MCP** por owner; la novena recibe `too_many_sessions`.»
- **S17** (PRD §7.1, grilla): «Grilla de dos familias de líneas diagonales (±32°) que forman rombos, 1 px, sobre un color base. Defaults tomados de la referencia visual: base `#1b1b1b`, línea `#ffffff` a 14% de opacidad, separación 59 px, ángulo 32°.» · «La grilla es chrome del frontend**, no parte del SVG: los exports (RF10) salen limpios y el determinismo O8 no se ve afectado.»
- **S18** (PRD §7.2, grilla y cámara): «La separación de grilla (59 px) es del **espacio del plano** y **escala con el zoom**; el grosor de línea se fija en 1 px de pantalla.» · «`devicePixelRatio` afecta solo el **grosor** de la grilla (1 px de pantalla); el resto del plano escala en unidades CSS.»
- **S19** (PRD §7.2, propiedad de la cámara): «La cámara **vive en el frontend**: `view = { tx, ty, zoom }` en píxeles de plano. Rust **nunca** escribe la cámara: emite intenciones (`place`, `focus`, `fit`) y el frontend las aplica. Rust guarda solo una **copia** (`CameraSnapshot`) que el frontend le empuja con el evento `camera-changed` (throttle 100 ms), para poder calcular "el centro de la vista actual".»
- **S20** (PRD §7.3, matriz RNF1-bis): «Se mide con 4 casos fijos por motor, no con un número suelto: `100n/150e` sin grupos · `100n/400e` sin grupos · `100n/150e` + 8 clusters · `300n/600e` sin grupos. Objetivo p95 en la máquina de referencia del CI (Linux x86_64, 4 vCPU, 8 GB, SSD): **< 500 ms** para los tres primeros y **< 1.5 s** para el de 300 nodos, con `DagreEngine` en frío (no hay caché de layout, por diseño determinista).»
- **S21** (PRD §11, `render_diagram`): salida «`{ ok, diagram_id, rendered_kind, rendered: bool, replaced?, metrics: {nodes, edges, layout_ms, render_ms, svg_bytes}, errors?: [...], warnings?: [...] }`»
- **S22** (PRD §8.6.1, estado): «El **modelo de diagramas vive en Rust** (`DiagramStore`); el frontend no es fuente de verdad. Al crear o recrear el webview, Rust emite `graphium://state` con la lista completa `{diagram_id, title, kind, updated_at, pos, bbox, session_id}»»
- **S23** (decisión de producto, 2026-11-03, respuesta del usuario): la grilla del plano se implementa con **CSS gradient** (dos familias `repeating-linear-gradient` a ±32°), no con canvas 2D; **«separación 59 px» = la diagonal mayor (horizontal) del rombo**, de modo que el paso perpendicular entre líneas paralelas es `59 · sin(32°) ≈ 31.26 px` y el lado del rombo ≈ 31.26 px. La separación es del espacio del plano y escala con el zoom; el grosor queda en 1 px de pantalla (S18), y el fondo `#1b1b1b` con línea `#ffffff` al 14% es chrome del frontend, nunca del SVG exportado (S17).

- **L6** (2026-11-03, decisión de ingeniería F0 que resuelve una ambigüedad del PRD): los traits `LayoutEngine`, `TextMetrics` y `SvgRenderer` se **definen en `gx-core`** y se implementan en `gx-layout` y `gx-render-svg`. Motivo: §9.1 exige que `gx-core` no dependa de nada y a la vez que la puerta única `gx_core::engine::render_json` viva en `gx-core`; si los traits vivieran en `gx-layout`/`gx-render-svg` habría ciclo. No contradice la matriz de dependencias: los crates siguen dependiendo solo de `gx-core`.
- **L7** (2026-11-03, decisión de ingeniería F0): la puerta única resuelve los motores por **inyección global** (`gx_core::engine::install(Engines { layout, metrics, renderer })`) porque `gx-core` no puede conocer `dagre` ni `rustybuzz`. El binario (`gx-app`) instala los motores reales al arrancar; los tests de `gx-mcp` instalan motores stub, así que ningún test de RNF6 necesita Tauri, webkit ni webview (S5).
- **L8** (2026-11-03, desviación mecánica del PRD): se usa `schemars` **1.2.3**, donde el tipo del schema se llama `schemars::Schema` y no `schemars::schema::RootSchema` como escribe §8.1-8.3. El rename no cambia el contrato: el schema sigue saliendo del `derive(JsonSchema)` de la misma struct que se valida.
- **L9** (2026-11-03, decisión de ingeniería F0): el trait `DiagramKind` de §8.1-8.3 se conserva literal, pero el registro de §9.1 guarda un **`KindHandler` object-safe** (`KindAdapter<K>` lo implementa) porque `fn schema()` estático hace el trait no object-safe y `registry::for_kind(&str)` necesita dispatch dinámico por nombre. Consecuencia: el tamaño del nodo lo mide la puerta única con el `TextMetrics` inyectado antes del layout (no `to_ir()`, que no tiene el medidor a mano): la única fuente de métricas sigue siendo `gx-render-svg` (S11).
- **L10** (2026-11-03, desviación del PRD): `kind_data` es `BTreeMap<String, IrValue>` y no `BTreeMap<&'static str, IrValue>`, porque la IR tiene que poder serializarse para `--dump-last` (RNF7) y `Deserialize` de `&'static str` no existe.
- **L11** (2026-11-03, implementación de la grilla, cierra S23): la grilla es una capa fija (no escalada) con dos `repeating-linear-gradient` a ±32°; `--grid-step = 31.26 px × zoom` (paso perpendicular) y `--grid-line: 1px` (grosor de pantalla); el `background-position: -tx, -ty` da la fase correcta en las dos familias a la vez, porque el desplazamiento `-t` tiene exactamente la componente necesaria sobre el eje de cada familia y la componente restante es irrelevante (el patrón es invariante a lo largo de la línea).
- **L12** (2026-11-03, eventos de la ventana): Tauri 2 acepta `:` en los nombres de evento (verificado en `tauri-2.12.5`: se permiten alfanuméricos, `-`, `/`, `:` y `_`), así que se respetan los nombres del PRD (`graphium://render`, `graphium://ready`, `graphium://state`). Se agregan dos eventos de chrome que §7.2 describe pero no nombra: `graphium://pending` (tarjeta fantasma) y `graphium://error` (banner).
- **L13** (2026-11-03, fuentes): Inter 4.1 subseteado con fontTools a Latin-1 + Latin Ext-A: 404 glifos por peso, 57 KB (Regular) + 59 KB (Semibold), con el `kern` de GPOS intacto. Muy por debajo del presupuesto de 3 MB de RNF1-quater.
